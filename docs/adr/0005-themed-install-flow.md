# 0005 — Themed installation

- **Status:** Accepted
- **Date:** 2026-10-19
- **Proposed by:** product owner (radar items of 2026-10-19)
- **Accepted by:** product owner, 2026-10-19

## Context

Each world has a theme, and the installed app should look like it: the name under the icon and the icon follow the theme. Two platform facts shape the flow:

- iOS never updates an installed icon, so the theme has to be known before the app is installed.
- On iOS the installed app does not share storage with Safari. A join made in Safari is lost; the order has to be install first, join afterwards.

## Decisions

1. **One manifest per theme**, `manifest-{themeId}.webmanifest`, generated at build time from the `install` block of each `theme.json` (name, colours, icons). Each has its own `id`, so each theme is its own app. It starts on `?theme={themeId}`, so an installed app looks right from its first frame, even before it knows a world.
2. **The join link carries the theme id**: `<app URL>#/join/<worldId>/<themeId>`. The theme id is not secret. A joining device looks like the world before it joins.
3. **The page is themed only when the theme is known**: from a join link, from the choice made when creating a world, or from the world itself (remembered for the next launch). The manifest, the iOS icon, the iOS name and the colours are swapped then. The app never offers to install itself from the bare address.
4. **An install offer inside the app.** On Android and desktop Chrome, a button that opens the browser's dialog (`beforeinstallprompt`). On iOS, short steps with the theme's app name, because there is no API. Hidden when already installed.
5. **On iOS in a browser tab, a join link does not join.** It explains, offers the install steps, and offers to copy the link. In the installed app, a "paste" button joins from the clipboard, in one tap. In every other case a join link joins at once.
6. **The theme is chosen when the world is created and is fixed for it** (`SPEC.md` §1). The choice is offered only when there is more than one theme.

## Tried and dropped

A manifest without `start_url`, to let the installed app start on the join link itself. Chrome refuses to install it (`start-url-not-valid`), so Android would lose installation. The "paste" button replaces it. Whether iOS would have kept the URL fragment was not tested.

## Alternatives considered

- **A single manifest for all themes.** Simple, but the installed app would always carry the same name and icon.
- **Swapping the icon after installation.** Not possible on iOS.
- **Joining in the browser and installing afterwards.** Works on Android, where storage is shared, but loses the join on iOS.

## Consequences

- A new theme needs an `install` block and four PNG icons (`validate-theme` checks them).
- The page's manifest changes while the app runs. Browsers re-read it; this was checked in Chrome.
- A device that opens a join link on iOS sees no profile picker until it is in the installed app. The "paste" button makes this one tap.
- Icons are generated by hand (`public/icons/README.md`); the pirate theme brings its own art later.
