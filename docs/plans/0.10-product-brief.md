# Release 0.10 — Product brief: the settings menu, help, installation and versions

**Status: decided by the product owner (2026-10-24).** Written for the tech lead, who turns it into `docs/plans/0.10.md`, the `SPEC.md` changes and, if needed, an ADR.

It fills the 0.10 scope in `ROADMAP.md`: one place for definitions and configuration, in a menu that stays out of the main interface, and a check of new versions.

Neutral glossary only (`SPEC.md` §3). Pirate names are examples of a theme. Interface text below is European Portuguese, as it goes into the locale files. `{@term…}` and `{^@term…}` are the theme term forms of ADR 0006. Where a form does not exist yet, the tech lead may add it or reword the line, keeping the meaning.

---

## 1. The menu

- **Where:** a gear button (⚙) in the top right corner of the map's bar. This is the only new control on the map.
- **What moves into it:** the map's bar loses its "Trocar de perfil", "Gerir" and "Instalar" buttons. The greeting ("Olá, {name}!") stays on the left.
- **How it opens:** tapping ⚙ opens a panel over the map.
  - It closes with ✕, a tap outside it, or the system back gesture.
  - Tapping an item closes the panel and opens that screen.
  - Every screen opened from the menu has the usual top bar, and its back button returns to the map.
- **Contents, in this order:**

  | Item (pt-PT) | Who sees it | Opens |
  | --- | --- | --- |
  | Como jogar | everyone | §4 |
  | Como instalar | everyone | §5 |
  | — section heading "Definições" — | adults | |
  | Pessoas | adults | §2.1 |
  | Tarefas | adults | §2.2 |
  | Regras do jogo | adults | §2.3 |
  | Trocar de perfil | everyone | the profile picker; always the last item |
  | *(footer)* version, date and "Atualizar" | everyone | §7 |

  "Adults" means the active profile is an adult profile, which is the admin rule of ADR 0003. A child never sees the "Definições" section.
- **The "Gerir" screen disappears.** It is replaced by the three settings screens. Its route may stay only as a redirect to the map.
- **The `board` keeps its own entry to create tasks.**

## 2. Settings, as three screens

Each screen holds one job. The sections already exist in `src/ui/screens/`. This is mostly a regrouping; the changes in behaviour are marked **new**.

### 2.1 Pessoas

- The list of profiles, with archive and reactivate.
- **New: rename a profile.**
  - The name is trimmed, and empty is refused.
  - The limit is the same as creating (`LIMITS.displayName`).
  - Adults only, any profile. Check that the rules allow this change for an admin; if not, it needs a rules change, an ADR and a rules deploy by the product owner.
- The form for a new profile.
- The invite: the link and the QR code, which today sit behind "Mostrar link e QR code".
- **New: an invite per child.** Each child profile has its own "Convidar", with a link and a QR code that open the app already on that profile (§2.4). The general invite stays as it is.

### 2.2 Tarefas

One screen for every task, whether it repeats or not.

- **Per profile:** a choice of profile, then that profile's open tasks and the tasks done in the last days. This is today's adults' view (`SPEC.md` §7.8), with retire.
  - A task that comes from a repeating definition is marked as such, so one-off and repeating tasks sit in the same list.
- **The repeating definitions:** on the same screen, the list of definitions, with edit and deactivate.
- **"Nova tarefa":** opens the single task form, the same as from the `board`.

### 2.3 Regras do jogo

Each value keeps its own "Guardar" and validation, as today.

- **{^@token.plural}:**
  - tokens per difficulty;
  - price per tier.
- **Limites:**
  - the size of the `party`;
  - the places in the reserve (`showcaseSize`);
  - **new:** the days a new collectible stays pending (`pendingDays`). It is a whole number from 1 to 7, and the default stays 1. Today it can be configured but has no screen.
- **Reiniciar o mundo,** at the end of this screen, in the danger colour (§3).

### 2.4 Invite per child (new)

An adult shares a link or QR code per child. On the child's phone, joining lands directly on that child's profile, with no profile picker. Added on 2026-10-24.

- **The link:** the join link gains an optional profile part: `<app URL>#/join/<worldId>/<themeId>/<profileId>`.
  - The general link (without a profile) keeps working exactly as today.
  - Only the random profile id goes in the link, never the name or any other personal data.
- **A shortcut, not a login.** The profile is chosen only when the device joins the world for the first time. The device can still switch profile from the menu, as today, **except** a device that entered by a child's own link, which stays on that child (0.10.13, below). Real per-profile protection is the PIN in "Later" (`ROADMAP.md`).
- **Child profiles only.** Adult profiles get no personal link, because it would hand out admin rights directly (ADR 0003). Adults use the general invite.
- **Only on the first join.** On a device that already has an active profile in that world, the profile part is ignored and nothing changes. Opening a sibling's link never switches anyone's profile.
- **Fallbacks:** if the profile is archived, unknown, or an adult profile, the device joins and shows the usual profile picker, with no error.
- **iPhone:** the order "install first, then open the link" stays (ADR 0005).
  - Pasting the link in the installed app must carry the profile too.
  - The start-up carry of ADR 0014 (`?join=<worldId>.<profileId>`) already holds a world and a profile; the tech lead reuses it rather than adding a second mechanism.
- **Where to look in the code:**
  - `src/ui/routes.ts`: the `join` route and `hashFor`, `joinLink`, `parseJoinInput` (its pattern rejects a fourth part today), `parseCarry` and `carrySearch`;
  - the join screen (`src/ui/screens/join.ts`) and the invite screen (`src/ui/screens/share.ts`).
- **Older versions:** an app still running an older version refuses to paste the longer link, because of `parseJoinInput`. Tapping the link still works. Accepted, because "Atualizar" (§7) brings every phone to 0.10.
- **No rules change** is expected: the world id stays the only access code, and choosing a profile is already a device's own choice. If that turns out to be wrong, it needs an ADR and a rules deploy by the product owner.

## 3. Restarting: "Reiniciar o mundo"

- **Neutral words, not the theme's.** Every restart text (title, button, warning) says **"mundo"**, not the theme's world name. In the pirate theme it no longer reads "Reiniciar a ilha".
  - The texts move from `{@world.the}` to plain text in `src/i18n/pt-PT.json`: "Reiniciar o mundo".
  - If the creation flow shows the theme's world name where the product owner expects "mundo", it is aligned in the same change.
- **Behaviour unchanged** (ADR 0011): the same warning, the typed word, the same result.
- **Where:** the last block of "Regras do jogo", set apart from the values above it.

## 4. "Como jogar"

- **What it is:** one screen, for everyone. It is read-only text from the locale files, with the theme's terms filled in. The numbers come from the world's `ruleset`, so they are always the real ones.
- **The adults' section** shows only when the active profile is an adult.
- **What it never shows:** no counts about people, and no comparisons.
- **Opens by itself once:** the first time a profile is chosen on a device, "Como jogar" opens by itself, once.
  - It is remembered on the device, per profile, and never opens by itself again.
  - It is always in the menu.
  - Profiles already in use when 0.10 is installed also see it once.

Proposed text (pt-PT). The product owner reviews it on a phone before 0.10 closes:

> **As tuas tarefas**
> {^@board.the} mostra o que tens para fazer. Quando tem novidades, aparece um balão por cima.
>
> **Fazer uma tarefa**
> Quando acabares uma tarefa, marca-a como feita {@checkin.in}. Se houver uma pergunta, responde com verdade. Enganaste-te? Tens uns segundos para desfazer.
>
> **Ganhar {@token.plural}**
> Cada tarefa feita dá {@token.plural}: as fáceis dão {low}, as médias {mid} e as difíceis {high}. Nunca se perdem.
>
> **Abrir {@reward.plural}**
> {^@vault.in} trocas {@token.plural} por {@reward.plural}: custam {lowPrice}, {midPrice} ou {highPrice}. Os mais caros trazem {@collectible.plural} mais raros. Abres já, ou juntas para um melhor: a escolha é tua.
>
> **{^@party}**
> Cada {@reward} traz {@collectible.a}. Podes deixá-lo entrar {@party.in} e dar-lhe um nome, ou deixá-lo ir para {@reserve.the}. Cabem {partySize} {@party.in}; se já não houver lugar, escolhes quem sai.
>
> **{^@showcase}**
> {^@showcase.in} ficam os últimos {showcaseSize} que alguém deixou ir. Qualquer pessoa pode levar um para {@party.the}. Quando chegam novos, os mais antigos vão-se embora para sempre.
>
> **{^@home}**
> {^@home.in} vês {@party.the} e escolhes o teu símbolo.
>
> **Para os adultos** *(adults only)*
> Criam-se tarefas {@board.in} ou nas definições: uma vez ou a repetir, para uma ou mais pessoas. A dificuldade decide quantas {@token.plural} a tarefa dá. As definições estão na roda dentada, em cima à direita. Ninguém vê o que os outros têm, nem quanto ganharam.

Two notes on the text:

- Words that agree in gender with a theme term ("deixá-lo") must follow the term's `gender`, or be reworded so they do not depend on it.
- The pirate theme should read naturally, and so should the minimal themes.

## 5. "Como instalar"

- **Name:** the menu item and the screen are called "Como instalar" (was "Instalar").
- **What the screen shows depends on the device:**

  | Device | The screen shows |
  | --- | --- |
  | Already installed | "A app já está instalada neste telemóvel." |
  | Android or desktop Chrome, when the browser allows installing | the "Instalar" button (the browser's dialog) and one line explaining it |
  | iPhone or iPad in Safari | the steps: Partilhar, then "Adicionar ao ecrã principal", with the theme's app name |
  | Anything else | "Abre este endereço no Chrome (Android) ou no Safari (iPhone)." |

- **Always, at the end:** "Para outra pessoa entrar: instala primeiro e só depois abre o link de convite." This matters on iPhone, where a join made in Safari is lost (ADR 0005).
- **Unchanged:** the install offers elsewhere (join flow, first launch) stay as ADR 0005 describes.

## 6. The installed app's icon and name

### Check it first

The installed app shows the icon and the name of the chosen world's theme, never the generic ones. ADR 0005 already designs this (one manifest per theme, the theme applied before installing).

- The tech lead checks it end to end on an Android phone and an iPhone, from creating a world and from a join link.
- If either phone shows another icon or name, it is a bug, fixed with a test that fails without the fix.
- **Known platform limit, accepted by the product owner:**
  - iOS never changes the icon of an app already installed, so an iPhone must remove and reinstall the app to see the new icon;
  - Android updates it by itself, after some time.

### Pirate theme

- **Name:** the pirate theme's `install.name` becomes **"Ilha dos Piratas"** (today "Piratas do Farol").
  - The theme's own name, shown when choosing a theme, stays "Piratas do Farol".
  - The name under the icon always comes from the theme, never from the name a family gives its world.
- **Icon:** the parrot's face, the one the `board` shows for news.
  - The face is taken from the pirate `board` art, made for this repository under MIT, and goes through `npm run art:prepare` and `credits.json`.
  - Every install size is produced: 192, 512, maskable 512 with the face inside the safe zone, and the 180 Apple icon with an opaque background.
  - `validate-theme` passes.

## 7. Version, date and updating

- **The footer:** the menu's footer shows the running version and its build date. Example: "Versão 0.10.0 · 24/10/2026", with the date in Lisbon time, injected at build like `__APP_VERSION__`.
- **When a newer version is published:** an **"Atualizar"** button shows next to it.
  - Tapping it loads the new version. Nothing is lost: queued writes are already persisted (`SPEC.md` §10).
- **When it checks:** when the app opens and when the menu opens.
- **Offline,** or if the check fails, there is no button and no error. The footer still shows the running version.
- **Nothing outside the menu:** no alert, dot or banner on the map for a new version.
- **The mechanism is for the tech lead** (the service worker's update, or a published version file read without cache). It stays within GitHub Pages and the Spark plan.

## 8. Documents the tech lead updates

- **`SPEC.md`:** §4 (`pendingDays` set in "Regras do jogo"), §5 (the join link with an optional child profile), §7 (the map's bar and the menu; management becomes the three settings screens; profile rename; "Como jogar"; "Como instalar"; version and update) and §8 (the theme's install name and icon).
- **`README.md`,** if it mentions "Gerir" or "Instalar".
- **`CHANGELOG.md`, `ROADMAP.md`, `docs/plans/0.10.md`.**
- **An ADR is needed if:** the install check in §6 changes how manifests or icons are chosen, if renaming a profile needs a rules change, or for the update check in §7.
- **An ADR is needed for:** the join link format (§2.4), because it is a contract that links already shared depend on. It may amend ADR 0005 and ADR 0014 rather than stand alone.

## 9. Exit criteria

- The map's bar has only the greeting and ⚙.
- A child's menu has no "Definições" section, and "Trocar de perfil" is always the last item, except on a device that entered by that child's own link (0.10.13).
- Every former management section is reachable in at most 2 taps from the map (⚙, then the item).
- "Reiniciar o mundo" shows no theme word.
- **The child's invite (§2.4):**
  - a new phone that opens a child's link or QR code lands on that child's profile, on Android and on iPhone (install, then paste);
  - the general link still shows the profile picker;
  - a phone already in the world keeps its profile;
  - an archived profile falls back to the picker;
  - route tests cover the new link, the old link and each fallback.
- "Como jogar" opens by itself once per profile and device, and never again.
- With a newer version published, "Atualizar" shows in the menu and loads it. Offline, nothing shows and nothing fails.
- On an Android phone and an iPhone, a fresh install from a join link to a pirate world shows the parrot icon and "Ilha dos Piratas".
- The product owner reads "Como jogar" on a phone, in the pirate theme and in one minimal theme, and accepts the text.

## 2.5 A device that entered by a child's link stays on that child (added 2026-10-25)

Decided by the product owner on 2026-10-25, **only for a device that entered by a child's own link** (§2.4):

- it has no "Trocar de perfil" and no profile picker;
- it is a remedy against mistakes, not security (§2.4 stays: the link is a shortcut, not a login);
- clearing the app's data is the only way to free it, and it frees itself if the profile is archived;
- a device that enters by the general link, with an adult profile, or by the carry of an app added to an iPhone's home screen is not fixed.
